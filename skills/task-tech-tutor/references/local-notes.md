# Local learning documents

Read before every technology-map, learning-note, or handoff write. These safeguards implement the skill's Git boundary; they do not grant publication permission.

1. Store documents in `<project-root>/.ai-skill-local/task-tech-tutor/`; default to `TASK_TECH_NOTES.md` there. The hidden `.ai-skill-local/` folder is shared by skills, with one subfolder per skill. Use distinct task filenames when needed; preserve learner history and never overwrite unrelated files or another task's notes. Create only required directories and learning documents; never write through symlinked paths. If project instructions prohibit this location, continue conversationally rather than writing elsewhere in the repository.
2. In Git, resolve the repository root and local exclusion file with read-only commands, including `git rev-parse --git-path info/exclude` for linked worktrees. Before creating directories or writing documents, check the entire `.ai-skill-local/` directory with `git --literal-pathspecs ls-files -- <artifact-directory>`. If it contains tracked paths, leave documents untouched; never remove files from the index to enable persistence.
3. Append the missing directory rule to local `info/exclude`, preserving existing entries. Use `/.ai-skill-local/`, prefixed by the project's relative path when nested and escaped for Git ignore metacharacters. Exclude this whole artifact directory, never a source directory. Ensure the local rule exists even when project or global ignores already cover it.
4. Before each write, verify the artifact directory has no tracked paths, its local directory rule remains present, and every destination is ignored with `git check-ignore`. If tracking, permissions, conflicting patterns, unavailable Git commands, or unsafe paths prevent verification, leave documents untouched and provide their content in conversation. Do not edit project/global ignore files, Git configuration, or tracked documents as a workaround. Never stage, commit, or force-add these artifacts.
5. Outside Git, use the same folder without initializing Git. If it is unwritable, continue without saving.
6. When the new document is absent, existing root-level technology notes may be read and their learner history copied into the new location after these safeguards pass. Leave originals and their exclusions untouched; report legacy paths for user-reviewed cleanup. If both locations exist, use the new document and surface conflicting history rather than silently overwriting it.

Record concise source-linked versions, technology targets, demonstrated understanding, remaining gaps, and readiness; omit source dumps and secrets. Report saved paths or unsaved progress in the handoff. Recheck relevant project versions before reusing saved lessons after project changes.
